# Contributor guide

Read README.md and docs/design.md before modifying the public API. Preserve error semantics, source attribution, scope boundaries and concurrency guarantees. Update documentation and executable examples together with behavior changes. Never commit credentials, generated build output, personal transcripts or database files. Keep commits conventional and focused.

Run the checks documented in README.md before declaring a change ready. Tests must cover observable guarantees and failure cases. Do not describe benchmark results or deployment maturity without recorded evidence.
